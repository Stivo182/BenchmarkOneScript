# Управление итерациями и вызовами

## Количество итераций

Контролирует количество измерительных итераций для основных этапов (измерение и память).

### Аннотация

```bsl
&КоличествоИтераций(25)
Процедура ПриСозданииОбъекта()
	// ...
КонецПроцедуры
```

### API

```bsl
Конфигурация.УстановитьКоличествоИтераций(25);
```

### CLI

```bash
benchos run --iterationCount 25 [FILE]
```

## Адаптивные итерации

По умолчанию количество измерений фиксировано. Чтобы завершать этап измерения после достижения заданной погрешности, включите адаптивный режим одним из способов ниже.

### Аннотация

`&АдаптивныеИтерации` применяется к `ПриСозданииОбъекта`, включает адаптивный режим и принимает необязательные именованные параметры: `МаксимальнаяОтносительнаяПогрешность`, `МинимальноеКоличествоИтераций` и `МаксимальноеКоличествоИтераций`.

```bsl
&АдаптивныеИтерации(
	МаксимальнаяОтносительнаяПогрешность = 0.1,
	МинимальноеКоличествоИтераций = 15,
	МаксимальноеКоличествоИтераций = 100
)
Процедура ПриСозданииОбъекта()
КонецПроцедуры
```

Допустимые значения и значения по умолчанию приведены в разделе [«Параметры и ограничения»](#параметры-и-ограничения).

### API

```bsl
Конфигурация
	.ВключитьАдаптивныеИтерации()
	.УстановитьЦелевуюОтносительнуюПогрешность(0.1) // не более 10%: погрешность среднего / среднее при доверительной вероятности 99,9%
	.УстановитьМаксимальноеКоличествоАдаптивныхИтераций(100) // не выполнять более 100 измерений
	.УстановитьМинимальноеКоличествоАдаптивныхИтераций(15); // выполнить не менее 15 измерений
```

Если цель не достигнута к максимуму, запуск завершается и отчёт получает предупреждение. В фиксированном режиме это же значение служит ориентиром предупреждения о высокой относительной погрешности. Адаптивный режим применяется только к измерениям времени; фиксированный `КоличествоИтераций` остаётся режимом по умолчанию.

### CLI

В CLI передача любой из опций адаптивного режима включает его:

```bash
benchos run --maxRelativeError 0.1 --minAdaptiveIterationCount 15 --maxAdaptiveIterationCount 100 [FILE]
```

## Достоверность статистики

### Параметры и ограничения

| Настройка | По умолчанию | Ограничение | Назначение |
| --- | ---: | --- | --- |
| Максимальная относительная погрешность | `0.1` | Больше `0` | Цель остановки адаптивных итераций и ориентир предупреждения в фиксированном режиме. |
| Минимальное количество адаптивных итераций | `15` | Не меньше `2`; при статистическом сравнении - не меньше `15` | Число измерений до первой проверки погрешности. |
| Максимальное количество адаптивных итераций | `100` | Не меньше минимума | Верхняя граница числа измерений в адаптивном режиме. |
| Относительный порог практической значимости | `0.15` | От `0` включительно до `1` исключительно | Граница практически значимого различия с эталоном. |
| Уровень значимости статистического сравнения | `0.01` | Больше `0` и меньше `1` | Допустимая вероятность ошибки первого рода. |

### Когда выбирать режим

- Фиксированное число итераций выбирайте для воспроизводимого бюджета измерений.
- Адаптивные итерации - когда важнее завершить замеры после достижения целевой погрешности.
- Статистическое сравнение включайте при наличии эталона и не менее `15` измерений в каждой выборке.

### Доверительный интервал и погрешность

Для среднего времени рассчитывается двусторонний 99,9% доверительный интервал:

```
среднее ± t(0,9995; N - 1) × стандартная ошибка среднего
```

`t(0,9995; N - 1)` - критическое значение распределения Стьюдента с `N - 1` степенями свободы. Колонка `Error` показывает половину этого интервала, а относительная погрешность для адаптивного режима равна `Error / Mean`. При `N < 2` интервал и относительная погрешность не определяются.

Интервал интерпретируется при достаточно независимых и стационарных измерениях. В бенчмарке он прежде всего показывает стабильность прогона: периодическая нагрузка, изменение частоты процессора или общий тренд во времени могут нарушить эти предпосылки. Уровень 99,9% номинален для заранее фиксированного числа измерений; при адаптивной остановке после достижения погрешности покрытие не гарантируется.

### Выбросы

Выбросы определяются по правилу Тьюки. Для квартилей `Q1` и `Q3` рассчитывается межквартильный размах `IQR = Q3 - Q1`; выбросом считается замер вне границ:

```
Q1 - 1,5 × IQR .. Q3 + 1,5 × IQR
```

Такие измерения помечаются в результатах и учитываются в предупреждении. Они не исключаются автоматически: среднее, доверительный интервал и условие остановки адаптивного режима рассчитываются по всем измерениям. Выброс - повод исследовать причину нестабильности, а не основание незаметно удалить данные.

### Диагностика измерений

После сводной таблицы консольный отчет выводит диагностику, сгруппированную по методу бенчмарка и значениям его параметров. При сравнении нескольких исполняющих сред добавляется промежуточная группа Runtime: `метод → Runtime → параметры`. Метка `[!]` означает предупреждение, `[i]` — информационное сообщение.

Возможны следующие сообщения:

| Условие | Сообщение |
| -- | -- |
| `N < 2` | `[!] Недостаточно измерений: <N> (требуется: 2)` |
| Адаптивный режим достиг максимума, но относительную погрешность вычислить нельзя | `[!] Погрешность не удалось оценить (цель: <целевая>%, измерений: <N>)` |
| Адаптивный режим достиг максимума, но целевая относительная погрешность не достигнута | `[!] Погрешность: <фактическая>% (цель: <целевая>%, измерений: <N>)` |
| Фиксированный режим и относительная погрешность выше ориентира | `[i] Погрешность: <фактическая>% (ориентир: <целевая>%)` |
| В `ПропускнаяСпособность` с автоматическим подбором вызовов и без обработчиков итераций среднее время измерительной итерации меньше `МинимальноеВремяИтерации` | `[!] Итерация: <фактическое> мс (цель: <минимальное> мс, <количество> вызовов)` |
| Есть выбросы | `[i] Выбросы: <количество выбросов> из <N>` |

### Статистическое сравнение с эталоном

Сравнение по критерию Манна - Уитни выключено по умолчанию. Чтобы получить колонку `MannWhitney`, включите его явно; пороги можно оставить значениями по умолчанию или настроить. Колонка добавляется только при наличии эталона. Для результата требуется не менее 15 измерений в каждой выборке.

#### Аннотация

`&СтатистическоеСравнение` применяется к `ПриСозданииОбъекта`, включает сравнение с эталоном и принимает необязательные именованные параметры: `ОтносительныйПорогПрактическойЗначимости` и `УровеньЗначимости`.

```bsl
&СтатистическоеСравнение(
	ОтносительныйПорогПрактическойЗначимости = 0.15,
	УровеньЗначимости = 0.01
)
Процедура ПриСозданииОбъекта()
КонецПроцедуры
```

Допустимые значения и значения по умолчанию приведены в разделе [«Параметры и ограничения»](#параметры-и-ограничения).

#### API

```bsl
Конфигурация
	.ВключитьСтатистическоеСравнениеСЭталоном()
	.УстановитьОтносительныйПорогПрактическойЗначимости(0.15) // различия меньше 15% считаются практически незначимыми
	.УстановитьУровеньЗначимостиСтатистическогоСравнения(0.01); // допустимая вероятность ошибки первого рода
```

Результат бывает: «Эталон», «Быстрее», «Медленнее», «Практически одинаково», «Различие не обнаружено» или «Недостаточно данных».

#### CLI

В CLI передача любого из порогов включает сравнение; второй порог можно изменить при необходимости:

```bash
benchos run --practicalSignificanceThreshold 0.15 --significanceLevel 0.01 [FILE]
```

«Практически одинаково» возвращается, только если эквивалентность в пределах заданного практического порога подтверждена при выбранном уровне значимости. «Быстрее» и «Медленнее» требуют статистически значимого выхода за соответствующую границу; иначе возвращается «Различие не обнаружено». Сравнение основано на рангах замеров, поэтому его вывод может не совпасть с отношением средних (`Mean`) при многомодальном распределении или выбросах.

Статистическая значимость не равна практической: малое p-value не отменяет установленный практический порог. Как и для доверительного интервала, результат предполагает независимость измерений; связанные последовательные замеры могут сделать p-value чрезмерно оптимистичным.


## Количество вызовов за итерацию

Указывает, сколько раз метод бенчмарка должен быть вызван в течение одной итерации. 

Особенности:
- Если установлено `0`, то количество будет рассчитано автоматически.
- Игнорируется для стратегии [`ХолодныйЗапуск`](СтратегииЗапуска.md#холодный-запуск-cold-start).

### Аннотация

```bsl
&КоличествоВызововЗаИтерацию(1000)
Процедура ПриСозданииОбъекта()
	// ...
КонецПроцедуры
```

### API

```bsl
Конфигурация.УстановитьКоличествоВызововЗаИтерацию(1000);
```

### CLI

```bash
benchos run --invocationCount 1000 [FILE]
```


## Количество прогревочных итераций

Указывает количество прогревочных итераций для подготовки окружения перед выполнением основных замеров бенчмарка. Прогревочные итерации используются для стабилизации системы: прогрев кэшей, 
инициализация внешних ресурсов. Результаты этих итераций не учитываются в финальной статистике. 

Особенности:
- Игнорируется для стратегии [`ХолодныйЗапуск`](СтратегииЗапуска.md#холодный-запуск-cold-start).

### Аннотация

```bsl
&КоличествоПрогревочныхИтераций(10)
Процедура ПриСозданииОбъекта()
	// ...
КонецПроцедуры
```

### API

```bsl
Конфигурация.УстановитьКоличествоПрогревочныхИтераций(10);
```

### CLI

```bash
benchos run --warmupCount 10 [FILE]
```


## Минимальное время итерации

Указывает минимальное время выполнения одной итерации бенчмарка в миллисекундах. Используется для подбора количества вызовов за итерацию так, чтобы одна итерация длилась не меньше указанного времени.

Особенности:
- Игнорируется для стратегии [`ХолодныйЗапуск`](СтратегииЗапуска.md#холодный-запуск-cold-start).

### Аннотация

```bsl
&МинимальноеВремяИтерации(250)
Процедура ПриСозданииОбъекта()
	// ...
КонецПроцедуры
```

### API

```bsl
Конфигурация.УстановитьМинимальноеВремяИтерации(250);
```

### CLI

```bash
benchos run --iterationTime 250 [FILE]
```
