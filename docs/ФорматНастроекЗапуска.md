# Формат настроек запуска

Файл, переданный в `benchos run --settings`, должен быть UTF-8 JSON. Для обычного запуска достаточно объекта `Configuration`. Отсутствующие поля получают значения по умолчанию. Имена JSON-полей чувствительны к регистру.

## Быстрый старт

Создайте `settings.json`:

```json
{
  "Configuration": {
    "IterationCount": 20,
    "Exporters": ["ЭкспортерРезультатовБенчмарковВJson"],
    "ArtifactsDirectory": "./BenchmarkArtifacts"
  }
}
```

Запустите бенчмарки:

```text
benchos run --settings settings.json ./benchmarks
```

## Расширенный пример

```json
{
  "Configuration": {
    "IterationCount": 20,
    "WarmupCount": 3,
    "Parameters": [
      { "Name": "Размер", "Value": 100 }
    ],
    "ParameterSources": [
      { "FieldName": "Размер", "Source": "ПолучитьРазмеры" }
    ],
    "Handlers": [
      { "Event": "ПередВсеми", "Handler": "ОбработчикиБенчмарков.ПередВсеми" }
    ],
    "Columns": ["Метод", "Среднее", "Категория"],
    "Exporters": [
      "ЭкспортерРезультатовБенчмарковВJson",
      "ЭкспортерРезультатовБенчмарковВHtml"
    ],
    "RuntimeVersions": [
      { "Version": "stable", "Name": "Стабильная", "Baseline": true }
    ]
  }
}
```

## Корневой объект

| Поле | JSON-тип | По умолчанию | Использование в `benchos run` |
| --- | --- | --- | --- |
| `Configuration` | Объект | Конфигурация с библиотечными значениями по умолчанию | Применяется к каждому запускаемому типу. |

## Поля `Configuration`

Все поля объекта необязательны. «По умолчанию» означает значение до применения аннотаций. При холодном запуске `WarmupCount`, `InvocationCount` и `MinIterationTime` не используются.

Часто используемые поля:

| Поле | JSON-тип | По умолчанию | Допустимые значения и смысл |
| --- | --- | --- | --- |
| `IterationCount` | Число | `0` | `0` включает адаптивное определение числа временных измерений; положительное целое задаёт их точное число. |
| `MaxRelativeError` | Число | `0.1` | Цель адаптивного режима: `Error / Mean`, больше `0`. |
| `MinAdaptiveIterationCount` | Число | `15` | Минимум измерений до проверки погрешности, не меньше `2`; при статистическом сравнении - не меньше `15`. |
| `MaxAdaptiveIterationCount` | Число | `100` | Максимум измерений в адаптивном режиме, не меньше минимума. |
| `StatisticalComparison` | Булево | `false` | Включает сравнение с эталоном по критерию Манна - Уитни и колонку `MannWhitney`; требуется не менее 15 измерений в каждой выборке. |
| `StatisticalComparisonRelativeThreshold` | Число | `0.15` | Относительная граница практически значимого сдвига выборки относительно эталона, например `0.05` для 5%; не меньше `0` и меньше `1`. |
| `StatisticalComparisonSignificanceLevel` | Число | `0.01` | Уровень значимости: допустимая вероятность ошибки первого рода; больше `0` и меньше `1`. |
| `InvocationCount` | Число | `0` | Не меньше `0`; `0` включает автоматический расчёт. |
| `WarmupCount` | Число | `6` | Не меньше `0`. |
| `Memory` | Булево | `false` | Включает отдельный этап измерения памяти. |
| `ArtifactsDirectory` | Строка | `.\BenchmarkArtifacts` | Каталог экспортируемых отчётов. |
| `Exporters` | Массив строк | `[]` | Полные имена типов экспортёров: `ЭкспортерРезультатовБенчмарковВMarkdown`, `ЭкспортерРезультатовБенчмарковВJson`, `ЭкспортерРезультатовБенчмарковВHtml`. |

Расширенные поля:

| Поле | JSON-тип | По умолчанию | Допустимые значения и смысл |
| --- | --- | --- | --- |
| `Strategy` | Строка | `ПропускнаяСпособность` | `ПропускнаяСпособность` или `ХолодныйЗапуск`. |
| `MinIterationTime` | Число | `100` | Минимальное время итерации в миллисекундах, больше `0`. |
| `MinInvocationCount` | Число | `4` | Больше `0`. |
| `ReportSorting` | Строка | `ПоУмолчанию` | `ПоУмолчанию`, `ОтБыстрыхКМедленным`, `ОтМедленныхКБыстрым`, `Метод`. |
| `Parameters` | Массив объектов | `[]` | Общие параметры полей бенчмарка; формат элемента ниже. |
| `ParameterSources` | Массив объектов | `[]` | Источники общих параметров; формат элемента ниже. |
| `Handlers` | Массив объектов | `[]` | Обработчики событий; формат элемента ниже. |
| `Columns` | Массив строк | `[]` | Дополнительные стандартные и пользовательские колонки. |
| `RuntimeVersions` | Массив объектов | `[]` | Пустой массив означает текущую среду; формат элемента ниже. |

Полный перечень стандартных и пользовательских колонок приведён в [справочнике `КолонкиОтчетаБенчмарков`](api/КолонкиОтчетаБенчмарков.md).

## Элементы вложенных массивов

Поля каждого элемента `Parameters`:

| Поле | JSON-тип | Обязательность / по умолчанию | Смысл в `benchos run` |
| --- | --- | --- | --- |
| `Name` | Строка | Нужно для применяемого параметра; иначе `""`. | Имя поля бенчмарка; определяет заменяемый `--param` параметр. |
| `Value` | Число, строка или булево | Нужно для значения; иначе `Неопределено`. | Значение общего параметра. |

Для пользовательского файла задавайте только `Name` и `Value`. Параметры должны иметь примитивные значения; составные значения передавайте через источник параметров.

Поля каждого элемента `ParameterSources`:

| Поле | JSON-тип | Обязательность / по умолчанию | Смысл в `benchos run` |
| --- | --- | --- | --- |
| `FieldName` | Строка | Обязательно для применяемого элемента. | Имя поля бенчмарка, значение которого задаёт источник. |
| `Source` | Строка | Обязательно для применяемого элемента. | Имя метода-источника из класса бенчмарка или `Тип.Метод`. |

Поля каждого элемента `Handlers`:

| Поле | JSON-тип | Обязательность / по умолчанию | Смысл в `benchos run` |
| --- | --- | --- | --- |
| `Event` | Строка | Нужно для применяемого обработчика; иначе `""`. | Событие: `ПередВсеми`, `ПослеВсех`, `ПередКаждымКейсом`, `ПослеКаждогоКейса`, `ПередИтерацией`, `ПослеИтерации`. `ПередКаждым` и `ПослеКаждого` оставлены для совместимости. |
| `Handler` | Строка | Нужно для применяемого обработчика; иначе `""`. | Имя метода класса бенчмарка, `Модуль.Метод` или `Тип.Метод`. |

Поля каждого элемента `RuntimeVersions`:

| Поле | JSON-тип | Обязательность / по умолчанию | Смысл в `benchos run` |
| --- | --- | --- | --- |
| `Version` | Строка | Нужно для выбора среды; иначе `""`. | Версия, канал `stable`/`dev` или путь к OneScript. |
| `Name` | Строка | Не требуется; `""`. | Подпись среды в отчёте. |
| `Baseline` | Булево | Не требуется; `false`. | Признак эталонной среды. |

Неизвестные JSON-поля игнорируются, поэтому проверяйте имена полей.

## Приоритет настроек

Приоритет действует только для настроек одного назначения. Например, `--method` и `--quiet` не конкурируют с полями JSON-конфигурации.

Приоритет от высшего к низшему:

1. Явно переданные опции `benchos run`.
2. Поля `Configuration` из `--settings`, значения которых отличаются от значений по умолчанию.
3. Аннотации класса бенчмарка.
4. Значения по умолчанию.

### Особые случаи

Для отдельных типов настроек действуют уточнения к этому порядку.

Значение из `--settings` переопределяет аннотацию, только если отличается от библиотечного значения по умолчанию. Исключение - положительное `IterationCount`: его присутствие в JSON значимо. Поэтому `"IterationCount": 15` переопределяет `&КоличествоИтераций(10)`, а `"IterationCount": 0` не переопределяет его.

Для коллекций правило применяется к каждой отдельно: изменённый непустой массив `Parameters`, `ParameterSources`, `Handlers`, `Columns`, `Exporters` или `RuntimeVersions` из `--settings` полностью заменяет одноимённую коллекцию, полученную из аннотаций. Явное `[]` совпадает с библиотечным значением по умолчанию, не считается изменением и потому не очищает коллекцию из аннотаций.

В отличие от этих коллекций, каждый `--param` заменяет только одноимённый параметр и его источник, сохраняя элементы с другими именами. `--exporters` задаёт полный список экспортёров и заменяет результат объединения `--settings` с аннотациями. `--method`, `--category`, `--quiet`, `--no-progress`, `--recursive`, `--debug` и входные `FILE` - настройки CLI; они не сериализуются в JSON.
